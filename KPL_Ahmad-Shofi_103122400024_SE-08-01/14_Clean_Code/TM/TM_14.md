## Deskripsi Tugas

Pada tugas mandiri ini diminta untuk membandingkan dua potongan kode JavaScript yang memiliki tujuan sama, yaitu memproses data user jika user tersebut memenuhi beberapa syarat.

Pertanyaan yang diberikan adalah:

> Dari dua kode di bawah ini, mana yang kamu ingin cari masalahnya dan perbaiki di tengah-tengah malam, katakanlah jam 1 malam? Mengapa?

Tugas ini berkaitan dengan prinsip **clean code**, terutama tentang keterbacaan kode, struktur kondisi, dan kemudahan melakukan debugging.

---

## Kode Pertama

```javascript
function processUser(user) {
  if (user) {
    if (user.isActive) {
      if (user.hasPermission) {
        return doSomething(user)
      }
    }
  }
  return null
}
```

---

## Kode Kedua

```javascript
function processUser(user) {
  if (!isValidCandidate(user)) return null;
  return doSomething(user);
}

function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```

Pada jam 1 malam, programmer biasanya sudah tidak dalam kondisi fokus penuh, sehingga kode yang sederhana dan tidak terlalu bertingkat akan jauh lebih aman untuk diperiksa.

## Penjelasan Kode Pertama

Kode pertama menggunakan struktur kondisi bertingkat atau **nested if**.

```javascript
function processUser(user) {
  if (user) {
    if (user.isActive) {
      if (user.hasPermission) {
        return doSomething(user)
      }
    }
  }
  return null
}
```

Pada kode tersebut, program memeriksa beberapa kondisi secara bertahap:

1. Apakah `user` ada.
2. Apakah `user.isActive` bernilai benar.
3. Apakah `user.hasPermission` bernilai benar.
4. Jika semua kondisi terpenuhi, maka fungsi `doSomething(user)` akan dijalankan.
5. Jika salah satu kondisi tidak terpenuhi, maka fungsi akan mengembalikan `null`.

Secara logika, kode ini benar. Namun dari sisi clean code, kode ini kurang nyaman dibaca karena memiliki terlalu banyak tingkatan indentasi.

Semakin banyak nested if, semakin sulit pembaca mengikuti alur program. Pembaca harus masuk dari satu kondisi ke kondisi lain sebelum memahami kapan fungsi utama dijalankan.

---

## Permasalahan pada Kode Pertama

### 1. Terlalu Banyak Nested If

Kode pertama memiliki beberapa kondisi yang bersarang:

```javascript
if (user) {
  if (user.isActive) {
    if (user.hasPermission) {
      return doSomething(user)
    }
  }
}
```

Struktur seperti ini membuat kode terlihat semakin masuk ke dalam. Jika kondisinya bertambah, maka kode akan semakin panjang ke kanan dan semakin sulit dibaca.

---

### 2. Alur Program Tidak Langsung Terlihat

Pada kode pertama, pembaca harus membaca beberapa kondisi terlebih dahulu sebelum mengetahui bahwa tujuan utama fungsi adalah menjalankan:

```javascript
doSomething(user)
```

Hal ini membuat maksud utama fungsi tidak langsung terlihat.

---

### 3. Lebih Sulit Saat Debugging

Jika terjadi error pada jam 1 malam, kode dengan nested if akan lebih melelahkan untuk diperiksa. Kita harus memperhatikan setiap tingkatan kondisi dan memastikan bagian mana yang gagal.

Dalam kondisi lelah, kode seperti ini lebih rawan menyebabkan kesalahan pembacaan.

---

### 4. Kurang Fleksibel Jika Kondisi Bertambah

Misalnya suatu saat syarat user bertambah, seperti:

```javascript
user.emailVerified
user.role === "admin"
user.notBlocked
```

Jika semua syarat ditambahkan dalam bentuk nested if, maka kode akan semakin rumit.

## Penjelasan Kode Kedua

Kode kedua menggunakan pendekatan yang lebih bersih.

```javascript
function processUser(user) {
  if (!isValidCandidate(user)) return null;
  return doSomething(user);
}

function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```

Pada kode ini, fungsi `processUser()` hanya memiliki dua langkah utama:

1. Jika user tidak valid, langsung kembalikan `null`.
2. Jika user valid, jalankan `doSomething(user)`.

Kode ini menggunakan prinsip **guard clause** atau pengecekan awal. Guard clause adalah teknik untuk memeriksa kondisi yang tidak valid di awal fungsi, lalu langsung menghentikan proses jika kondisi tersebut tidak terpenuhi.

---

## Mengapa Kode Kedua Lebih Baik?

### 1. Lebih Mudah Dibaca

Kode kedua lebih mudah dipahami karena alurnya sederhana:

```javascript
if (!isValidCandidate(user)) return null;
return doSomething(user);
```

Artinya, jika user tidak memenuhi syarat, fungsi langsung berhenti. Jika memenuhi syarat, program langsung memproses user tersebut.

---

### 2. Mengurangi Nested If

Kode kedua tidak memiliki kondisi yang bersarang terlalu dalam. Hal ini membuat struktur kode lebih datar dan rapi.

Kode yang datar lebih mudah dipahami dibandingkan kode yang terlalu banyak indentasi.

---

### 3. Menggunakan Nama Fungsi yang Jelas

Kode kedua memisahkan validasi user ke dalam fungsi:

```javascript
function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```

Nama fungsi `isValidCandidate()` menjelaskan bahwa fungsi tersebut digunakan untuk memeriksa apakah user layak diproses atau tidak.

Dengan nama fungsi yang jelas, pembaca tidak perlu menebak-nebak maksud dari kondisi:

```javascript
user && user.isActive && user.hasPermission
```

---

### 4. Lebih Mudah Dirawat

Jika suatu saat syarat user berubah, kita cukup mengubah fungsi `isValidCandidate()`.

Contohnya:

```javascript
function isValidCandidate(user) {
  return user &&
    user.isActive &&
    user.hasPermission &&
    user.emailVerified;
}
```

Dengan cara ini, fungsi `processUser()` tidak perlu diubah. Validasi tetap berada di satu tempat.

---

### 5. Lebih Aman Saat Diperbaiki dalam Kondisi Lelah

Pertanyaan tugas ini menggunakan contoh jam 1 malam. Pada waktu tersebut, programmer biasanya sudah lelah dan fokus berkurang.

Dalam kondisi seperti itu, kode yang lebih pendek dan jelas akan lebih aman untuk diperbaiki. Kode kedua mengurangi beban berpikir karena alurnya langsung terlihat.

---

## Prinsip Clean Code yang Digunakan pada Kode Kedua

### 1. Guard Clause

Kode kedua menggunakan guard clause:

```javascript
if (!isValidCandidate(user)) return null;
```

Guard clause membantu menghentikan proses lebih awal jika data tidak valid. Dengan cara ini, kode utama tidak perlu berada di dalam banyak kondisi `if`.

---

### 2. Meaningful Name

Fungsi `isValidCandidate()` memiliki nama yang jelas. Dari namanya saja, pembaca sudah bisa memahami bahwa fungsi ini digunakan untuk mengecek valid atau tidaknya user.

---

### 3. Single Responsibility Principle

Pada kode kedua, tanggung jawab fungsi lebih jelas.

| Fungsi               | Tanggung Jawab                            |
| -------------------- | ----------------------------------------- |
| `processUser()`      | Memproses user jika valid                 |
| `isValidCandidate()` | Mengecek apakah user valid untuk diproses |

Dengan pemisahan ini, setiap fungsi memiliki tugas yang lebih spesifik.

---

### 4. Readability

Kode kedua lebih mudah dibaca karena tidak memiliki banyak tingkatan indentasi. Kode seperti ini lebih nyaman dibaca, terutama ketika harus debugging dalam kondisi terburu-buru atau lelah.

---

### 5. Maintainability

Kode kedua lebih mudah dirawat. Jika aturan validasi user berubah, perubahan cukup dilakukan pada fungsi `isValidCandidate()`.

---

## Perbandingan Kode Pertama dan Kode Kedua

| Aspek                        | Kode Pertama                           | Kode Kedua                         |
| ---------------------------- | -------------------------------------- | ---------------------------------- |
| Struktur kondisi             | Banyak nested if                       | Menggunakan guard clause           |
| Keterbacaan                  | Lebih sulit dibaca                     | Lebih mudah dibaca                 |
| Indentasi                    | Terlalu dalam                          | Lebih datar                        |
| Debugging                    | Lebih melelahkan                       | Lebih mudah                        |
| Pemisahan tanggung jawab     | Validasi bercampur dengan proses utama | Validasi dipisah ke fungsi sendiri |
| Kemudahan perawatan          | Lebih sulit jika kondisi bertambah     | Lebih mudah jika kondisi berubah   |
| Cocok diperbaiki jam 1 malam | Kurang cocok                           | Lebih cocok                        |

## Kesimpulan

Dari dua kode yang diberikan, saya lebih memilih **kode kedua** untuk dicari masalahnya dan diperbaiki pada jam 1 malam.

Alasan utamanya adalah kode kedua lebih bersih, lebih mudah dibaca, dan lebih mudah dipahami. Kode kedua menggunakan guard clause untuk menghentikan proses lebih awal jika user tidak valid. Selain itu, validasi user dipisahkan ke dalam fungsi `isValidCandidate()`, sehingga fungsi `processUser()` tidak terlalu panjang dan tidak memiliki nested if yang dalam.

Kode pertama memang benar secara logika, tetapi kurang nyaman dibaca karena menggunakan beberapa `if` bertingkat. Dalam kondisi lelah, struktur nested if lebih berisiko menyebabkan kesalahan saat membaca atau memperbaiki kode.

Dengan demikian, kode kedua lebih sesuai dengan prinsip clean code karena lebih sederhana, lebih rapi, lebih mudah dirawat, dan lebih aman untuk diperbaiki ketika kondisi programmer tidak sepenuhnya fokus.
