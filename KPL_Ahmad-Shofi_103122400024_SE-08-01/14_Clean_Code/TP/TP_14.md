## Deskripsi Tugas

Pada tugas ini diminta untuk melakukan refaktorisasi terhadap sebuah kode JavaScript yang terlihat baik, tetapi masih melanggar beberapa prinsip kode bersih atau **clean code**.

Kode yang diberikan merupakan fungsi untuk menampilkan rincian pesanan di dalam modal. Fungsi tersebut mengambil data detail pesanan dari API berdasarkan `orderId`, lalu menampilkannya ke dalam modal. Jika user menekan tombol konfirmasi, maka sistem akan menyimpan atau mengonfirmasi pesanan tersebut.

Kode ini dimodifikasi dari repository:

```text
amrrwael/Delivery-website-Hits
```

Tujuan dari refaktorisasi ini adalah membuat kode menjadi lebih rapi, mudah dibaca, mudah dirawat, dan mengurangi kemungkinan bug.

## Kode Awal

Kode awal yang diberikan adalah sebagai berikut:

```javascript
function fetchOrderDetails(orderId, token) {
    fetch(`https://example.com/api/order/${orderId}`, {
        headers: {
            'Authorization': token
        }
    })
    .then(response => {
        if (!response.ok) {
            throw new Error('Failed to fetch order details');
        }
        return response.json();
    })
    .then(order => {
        // Display order info
        const modal = document.getElementById('orderModal');
        const detailsDiv = modal.querySelector('#orderDetails');
        detailsDiv.innerHTML = '';

        const header = document.createElement('h3');
        header.textContent = `Order ID: ${order.id}`;
        detailsDiv.appendChild(header);

        const status = document.createElement('p');
        status.textContent = `Status: ${order.status}`;
        detailsDiv.appendChild(status);

        // Show modal
        modal.style.display = 'block';

        // Setup close button
        const closeBtn = modal.querySelector('.close');
        closeBtn.addEventListener('click', () => {
            modal.style.display = 'none';
        });

        // Setup confirm button
        const confirmBtn = modal.querySelector('#confirmOrderBtn');
        if (order.status === 'Delivered') {
            confirmBtn.style.display = 'none';
        } else {
            confirmBtn.addEventListener('click', () => {
                confirmOrder(order.id, token);
            });
        }
    })
    .catch(error => {
        console.error('Error:', error);
    });
}
```

## Permasalahan pada Kode Awal

Kode awal sebenarnya dapat berjalan, tetapi masih memiliki beberapa kekurangan dari sisi clean code.

### 1. Fungsi Memiliki Terlalu Banyak Tanggung Jawab

Fungsi `fetchOrderDetails()` melakukan terlalu banyak pekerjaan sekaligus, yaitu:

1. Mengambil data dari API.
2. Mengecek response dari API.
3. Mengubah response menjadi JSON.
4. Mengambil elemen modal dari HTML.
5. Membuat elemen HTML untuk detail pesanan.
6. Menampilkan modal.
7. Mengatur tombol close.
8. Mengatur tombol konfirmasi.
9. Menangani error.

Hal ini melanggar prinsip **Single Responsibility Principle**, karena satu fungsi sebaiknya hanya memiliki satu tanggung jawab utama.

---

### 2. Kode Sulit Dibaca dan Dirawat

Karena semua proses ditulis dalam satu fungsi, kode menjadi panjang dan sulit dipahami. Jika ingin mengubah tampilan modal, maka harus mencari bagian kode yang bercampur dengan proses fetch API.

Jika ingin mengubah cara mengambil data dari API, maka kode tersebut juga masih bercampur dengan kode manipulasi DOM.

---

### 3. Terjadi Pengulangan Pembuatan Elemen

Pada kode awal, pembuatan elemen HTML dilakukan secara manual:

```javascript
const header = document.createElement('h3');
header.textContent = `Order ID: ${order.id}`;
detailsDiv.appendChild(header);

const status = document.createElement('p');
status.textContent = `Status: ${order.status}`;
detailsDiv.appendChild(status);
```

Jika nantinya ingin menambahkan elemen baru, kode akan semakin panjang dan banyak pengulangan.

---

### 4. Menggunakan Magic String

Kode awal langsung menulis status `"Delivered"` di dalam kondisi:

```javascript
if (order.status === 'Delivered') {
```

Nilai seperti ini disebut **magic string**. Jika status tersebut digunakan di banyak tempat, maka perubahan akan lebih sulit dilakukan. Lebih baik nilai tersebut disimpan dalam konstanta.

---

### 5. Event Listener Berpotensi Menumpuk

Pada kode awal, setiap kali fungsi `fetchOrderDetails()` dipanggil, kode akan menambahkan event listener baru:

```javascript
confirmBtn.addEventListener('click', () => {
    confirmOrder(order.id, token);
});
```

Jika modal dibuka berkali-kali, event listener juga dapat ikut bertambah. Akibatnya, ketika tombol konfirmasi diklik, fungsi `confirmOrder()` bisa terpanggil lebih dari satu kali.

---

### 6. Tombol Konfirmasi Berpotensi Tetap Tersembunyi

Pada kode awal, jika status pesanan adalah `"Delivered"`, tombol konfirmasi akan disembunyikan:

```javascript
confirmBtn.style.display = 'none';
```

Namun, ketika membuka pesanan lain yang statusnya belum delivered, tombol tersebut tidak secara jelas ditampilkan kembali. Hal ini bisa menyebabkan tombol konfirmasi tetap tersembunyi.

---

## Tujuan Refaktorisasi

Refaktorisasi dilakukan dengan tujuan sebagai berikut:

1. Membagi kode menjadi beberapa fungsi kecil.
2. Membuat setiap fungsi hanya memiliki satu tanggung jawab.
3. Membuat nama fungsi lebih jelas.
4. Mengurangi pengulangan kode.
5. Menghindari magic string.
6. Mencegah event listener menumpuk.
7. Membuat kode lebih mudah dikembangkan.

## Kode Setelah Refaktorisasi

Berikut adalah kode hasil refaktorisasi:

```javascript
const API_BASE_URL = "https://example.com/api";

const ORDER_STATUS = {
  DELIVERED: "Delivered",
};

function getOrderModalElements() {
  const modal = document.getElementById("orderModal");

  return {
    modal,
    detailsContainer: modal.querySelector("#orderDetails"),
    closeButton: modal.querySelector(".close"),
    confirmButton: modal.querySelector("#confirmOrderBtn"),
  };
}

async function fetchOrderDetails(orderId, token) {
  try {
    const order = await getOrderById(orderId, token);
    showOrderDetailsModal(order, token);
  } catch (error) {
    handleOrderDetailsError(error);
  }
}

async function getOrderById(orderId, token) {
  const response = await fetch(`${API_BASE_URL}/order/${orderId}`, {
    headers: {
      Authorization: token,
    },
  });

  if (!response.ok) {
    throw new Error("Failed to fetch order details");
  }

  return response.json();
}

function showOrderDetailsModal(order, token) {
  const {
    modal,
    detailsContainer,
    closeButton,
    confirmButton,
  } = getOrderModalElements();

  renderOrderDetails(detailsContainer, order);
  setupCloseButton(closeButton, modal);
  setupConfirmButton(confirmButton, order, token);
  openModal(modal);
}

function renderOrderDetails(container, order) {
  container.innerHTML = "";

  const header = createTextElement("h3", `Order ID: ${order.id}`);
  const status = createTextElement("p", `Status: ${order.status}`);

  container.appendChild(header);
  container.appendChild(status);
}

function createTextElement(tagName, text) {
  const element = document.createElement(tagName);
  element.textContent = text;
  return element;
}

function setupCloseButton(closeButton, modal) {
  closeButton.onclick = () => closeModal(modal);
}

function setupConfirmButton(confirmButton, order, token) {
  confirmButton.onclick = null;

  if (order.status === ORDER_STATUS.DELIVERED) {
    hideElement(confirmButton);
    return;
  }

  showElement(confirmButton);

  confirmButton.onclick = () => {
    confirmOrder(order.id, token);
  };
}

function openModal(modal) {
  modal.style.display = "block";
}

function closeModal(modal) {
  modal.style.display = "none";
}

function showElement(element) {
  element.style.display = "block";
}

function hideElement(element) {
  element.style.display = "none";
}

function handleOrderDetailsError(error) {
  console.error("Error:", error.message);
}
```

## Penjelasan Kode Setelah Refaktorisasi

### 1. Konstanta API dan Status Pesanan

Pada kode hasil refaktorisasi, URL API dan status pesanan dipindahkan ke dalam konstanta:

```javascript
const API_BASE_URL = "https://example.com/api";

const ORDER_STATUS = {
  DELIVERED: "Delivered",
};
```

Tujuannya agar kode lebih mudah dibaca dan tidak menggunakan magic string secara langsung di dalam logika program.

Jika suatu saat URL API berubah, maka perubahan cukup dilakukan pada bagian `API_BASE_URL`.

Jika nama status berubah, maka perubahan cukup dilakukan pada bagian `ORDER_STATUS`.

---

### 2. Fungsi `getOrderModalElements()`

Fungsi ini digunakan untuk mengambil elemen-elemen modal dari HTML.

```javascript
function getOrderModalElements() {
  const modal = document.getElementById("orderModal");

  return {
    modal,
    detailsContainer: modal.querySelector("#orderDetails"),
    closeButton: modal.querySelector(".close"),
    confirmButton: modal.querySelector("#confirmOrderBtn"),

```

Dengan fungsi ini, pengambilan elemen HTML menjadi lebih terpusat. Fungsi lain tidak perlu menulis ulang query selector berkali-kali.

---

### 3. Fungsi `fetchOrderDetails()`

Fungsi ini menjadi fungsi utama yang mengatur alur program.

```javascript
async function fetchOrderDetails(orderId, token) {
  try {
    const order = await getOrderById(orderId, token);
    showOrderDetailsModal(order, token);
```

Fungsi ini hanya bertugas mengambil data pesanan dan menampilkan modal. Detail proses pengambilan data dan tampilan modal dipisahkan ke fungsi lain.

Penggunaan `async await` juga membuat kode lebih mudah dibaca dibandingkan chaining `.then()` yang terlalu panjang.

### 4. Fungsi `getOrderById()`

### 5. Fungsi `showOrderDetailsModal()`

## Prinsip Clean Code yang Diterapkan

### 1. Single Responsibility Principle

Setiap fungsi dibuat hanya memiliki satu tanggung jawab utama.

| Fungsi                      | Tanggung Jawab                    |
| --------------------------- | --------------------------------- |
| `getOrderById()`            | Mengambil data pesanan dari API   |
| `renderOrderDetails()`      | Menampilkan data pesanan ke modal |
| `setupCloseButton()`        | Mengatur tombol close             |
| `setupConfirmButton()`      | Mengatur tombol konfirmasi        |
| `handleOrderDetailsError()` | Menangani error                   |

---

### 2. Meaningful Name

Nama fungsi dibuat jelas sesuai tugasnya.

Contoh:

```javascript
getOrderById()
showOrderDetailsModal()
renderOrderDetails()
setupConfirmButton()
```

Nama-nama tersebut memudahkan pembaca memahami fungsi kode tanpa harus membaca seluruh isi fungsinya terlebih dahulu.

---

### 3. Avoid Magic String

Status `"Delivered"` tidak langsung ditulis di dalam kondisi, tetapi dipindahkan ke konstanta:

```javascript
const ORDER_STATUS = {
  DELIVERED: "Delivered",
};
```

Hal ini membuat kode lebih mudah dirawat.

---

### 4. Avoid Repetition

Pembuatan elemen HTML dipindahkan ke fungsi:

```javascript
function createTextElement(tagName, text) {
  const element = document.createElement(tagName);
  element.textContent = text;
  return element;
}
```

Dengan fungsi tersebut, pembuatan elemen teks tidak perlu ditulis berulang-ulang.

---

### 5. Better Error Handling

Error ditangani melalui fungsi khusus:

```javascript
function handleOrderDetailsError(error) {
  console.error("Error:", error.message);
}
```

Dengan cara ini, kode utama menjadi lebih bersih dan mudah dipahami.

---

### 6. Prevent Duplicate Event Handler

Pada kode hasil refaktorisasi, tombol konfirmasi dibersihkan terlebih dahulu sebelum diberi aksi baru:

```javascript
confirmButton.onclick = null;
```

Hal ini dilakukan untuk mencegah event klik menumpuk ketika modal dibuka berkali-kali.

## Perbandingan Kode Awal dan Kode Refaktorisasi

| Aspek           | Kode Awal           | Kode Refaktorisasi                  |
| --------------- | ------------------- | ----------------------------------- |
| Struktur fungsi | Satu fungsi panjang | Banyak fungsi kecil                 |
| Tanggung jawab  | Bercampur           | Dipisah sesuai fungsi               |
| Pembacaan kode  | Lebih sulit         | Lebih mudah                         |
| Magic string    | Ada                 | Dikurangi dengan konstanta          |
| Event listener  | Berpotensi menumpuk | Dibersihkan dengan `onclick = null` |
| Perawatan kode  | Lebih sulit         | Lebih mudah                         |
| Reusable code   | Kurang              | Lebih reusable                      |

## Kesimpulan

Refaktorisasi dilakukan untuk memperbaiki struktur kode agar lebih sesuai dengan prinsip clean code. Pada kode awal, fungsi `fetchOrderDetails()` memiliki terlalu banyak tanggung jawab karena melakukan proses fetch API, manipulasi DOM, pengaturan modal, pengaturan tombol, dan penanganan error dalam satu tempat.

Setelah direfaktorisasi, kode dipisahkan menjadi beberapa fungsi kecil dengan tanggung jawab masing-masing. Fungsi `getOrderById()` digunakan untuk mengambil data pesanan, `renderOrderDetails()` digunakan untuk menampilkan data pesanan, `setupConfirmButton()` digunakan untuk mengatur tombol konfirmasi, dan `handleOrderDetailsError()` digunakan untuk menangani error.

Dengan refaktorisasi ini, kode menjadi lebih bersih, lebih mudah dibaca, lebih mudah dirawat, dan lebih aman dari bug seperti event listener yang menumpuk atau tombol konfirmasi yang tidak muncul kembali.

Secara keseluruhan, refaktorisasi membuat program lebih terstruktur tanpa mengubah tujuan utama program, yaitu menampilkan detail pesanan di modal dan mengonfirmasi pesanan ketika tombol konfirmasi diklik.
