## Deskripsi Tugas

Pada tugas ini diminta untuk membuka repository kode tugas besar, kemudian mencari satu design pattern yang digunakan di dalam project. Design pattern yang dipilih boleh design pattern apa saja, selama dapat dibuktikan melalui kode program dan dijelaskan desainnya.

Repository yang dianalisis adalah project **Foodora Catering App**, yaitu aplikasi pemesanan katering berbasis web. Aplikasi ini menggunakan **React.js** pada bagian frontend, **Node.js + Express.js** pada bagian backend, dan **MySQL** sebagai database.

Berdasarkan hasil pemeriksaan kode, salah satu design pattern yang digunakan dalam project ini adalah **Singleton Pattern** pada bagian koneksi database.

---

## Design Pattern yang Digunakan

Design pattern yang ditemukan pada project ini adalah:

```txt
Singleton Pattern
```

Singleton Pattern adalah design pattern yang memastikan sebuah object hanya dibuat satu kali, lalu digunakan bersama oleh bagian lain dalam aplikasi.

Pada project Foodora Catering App, Singleton Pattern diterapkan pada file koneksi database, yaitu:

```txt
backend/db.js
```

File tersebut membuat satu object `pool` untuk koneksi database MySQL. Object `pool` kemudian diekspor dan digunakan oleh file lain, terutama `backend/server.js`.

---

## Alasan Memilih Singleton Pattern

Singleton Pattern dipilih karena koneksi database sebaiknya tidak dibuat berulang-ulang di setiap endpoint atau setiap kali ada request dari user.

Jika setiap endpoint membuat koneksi database sendiri, maka aplikasi dapat menjadi lebih boros resource dan berisiko mengalami masalah koneksi. Dengan Singleton Pattern, aplikasi cukup membuat satu database connection pool, kemudian connection pool tersebut dipakai ulang oleh seluruh proses backend.

Pada Node.js, penerapan Singleton Pattern dapat dilakukan melalui sistem module. Ketika sebuah file diekspor menggunakan `module.exports`, lalu diambil menggunakan `require()`, Node.js akan menggunakan cache module sehingga object yang sama dapat digunakan kembali.

| File | Fungsi |
| --- | --- |
| `backend/db.js` | Membuat dan mengekspor database connection pool |

## Kode Implementasi Singleton Pattern

### File `backend/db.js`

```javascript
const mysql = require("mysql2/promise");
require("dotenv").config();

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  port: process.env.DB_PORT || 3306,
  waitForConnections: true,
  connectionLimit: 10,
  queueLimit: 0,
});

module.exports = pool;
```

## Kode Penggunaan Singleton

### File `backend/server.js`

```javascript
const pool = require("./db");
```

Kode di atas digunakan untuk mengambil object `pool` dari file `db.js`.

Contoh penggunaan `pool` pada endpoint pengecekan database:

```javascript
app.get("/api/health", async (req, res) => {
  try {
    const [rows] = await pool.query("SELECT 1 AS status");

    res.json({
      success: true,
      message: "Database terhubung",
      data: rows[0],
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Database gagal terhubung",
      error: error.message,
    });
  }
});
```

Contoh penggunaan `pool` pada proses pesanan:

```javascript
app.post("/api/pesanan", async (req, res) => {
  const connection = await pool.getConnection();

  try {
    const { id_user, items, metode_pembayaran, tanggal_booking } = req.body;

    if (!id_user || !Array.isArray(items) || items.length === 0) {
      return res.status(400).json({
        success: false,
        message: "Silakan login dan pilih minimal 1 menu sebelum membuat pesanan.",
      });
    }

    await connection.beginTransaction();

    // proses query database dilakukan di sini

    await connection.commit();
  } catch (error) {
    await connection.rollback();

    res.status(500).json({
      success: false,
      message: error.message,
    });
  } finally {
    connection.release();
  }
});
```

## Penjelasan Desain

Pada file `backend/db.js`, aplikasi membuat database connection pool menggunakan fungsi `mysql.createPool()`.

```javascript
const pool = mysql.createPool({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  port: process.env.DB_PORT || 3306,
  waitForConnections: true,
  connectionLimit: 10,
  queueLimit: 0,
});
```

Object `pool` berisi konfigurasi koneksi database, seperti host, user, password, nama database, port, dan batas jumlah koneksi.

Setelah object `pool` dibuat, object tersebut diekspor menggunakan kode berikut:

```javascript
module.exports = pool;
```

Dengan cara ini, file lain tidak perlu membuat koneksi database baru. File lain cukup memanggil:

```javascript
const pool = require("./db");
```

Kemudian object `pool` yang sama dapat digunakan untuk menjalankan query database.

Contohnya pada endpoint `/api/health`, object `pool` digunakan untuk menjalankan query sederhana:

```javascript
const [rows] = await pool.query("SELECT 1 AS status");
```

Selain itu, pada proses pembuatan pesanan, object `pool` juga digunakan untuk mengambil connection:

```javascript
const connection = await pool.getConnection();
```

Artinya, satu object pool yang dibuat di `db.js` dapat digunakan berkali-kali oleh banyak endpoint di `server.js`.

## Alur Kerja Singleton Pattern pada Project

Alur kerja Singleton Pattern pada project ini adalah sebagai berikut:

```txt
backend/db.js
    ↓
Membuat satu object pool database
    ↓
module.exports = pool
    ↓
backend/server.js mengambil pool dengan require("./db")
    ↓
Endpoint backend menggunakan pool yang sama untuk query database
```

Dengan desain seperti ini, koneksi database menjadi lebih terpusat dan tidak dibuat berulang-ulang.

## Analisis Design Pattern

Singleton Pattern pada project ini memiliki beberapa bagian penting:

1. **Single Instance**  
   Object `pool` hanya dibuat satu kali di file `backend/db.js`.

2. **Global Access Point**  
   Object `pool` dapat digunakan oleh file lain melalui `require("./db")`.

3. **Reusable Connection**  
   Object `pool` digunakan kembali oleh banyak endpoint di `backend/server.js`.

4. **Efisiensi Resource**  
   Aplikasi tidak perlu membuat koneksi database baru secara manual di setiap endpoint.

5. **Kode Lebih Rapi**  
   Konfigurasi database hanya berada di satu file, sehingga lebih mudah dirawat.

---

## Kelebihan Penerapan Singleton Pattern

Penerapan Singleton Pattern pada koneksi database memiliki beberapa kelebihan, yaitu:

1. Koneksi database lebih efisien karena menggunakan satu connection pool.
2. Konfigurasi database lebih mudah dikelola karena berada dalam satu file.
3. Endpoint backend tidak perlu menulis ulang konfigurasi database.
4. Kode menjadi lebih rapi dan mudah dipelihara.
5. Jika konfigurasi database berubah, perubahan cukup dilakukan pada file `db.js`.

---

## Catatan

Penerapan Singleton Pattern pada project ini bukan menggunakan class Singleton seperti pada contoh klasik Object Oriented Programming. Namun, konsepnya tetap sama karena object `pool` dibuat satu kali di dalam module `db.js`, kemudian digunakan kembali oleh file lain melalui `require()`.

Dengan kata lain, implementasi ini dapat disebut sebagai Singleton berbasis module pada Node.js.

## Kesimpulan

Berdasarkan hasil analisis repository Foodora Catering App, ditemukan penerapan **Singleton Pattern** pada file `backend/db.js`.

Design pattern ini digunakan untuk membuat satu database connection pool yang dipakai bersama oleh backend. Object `pool` dibuat satu kali menggunakan `mysql.createPool()`, lalu diekspor menggunakan `module.exports`. Setelah itu, file `server.js` menggunakan object tersebut melalui `require("./db")`.

Penerapan Singleton Pattern membuat koneksi database menjadi lebih efisien, terpusat, dan mudah dikelola. Dengan desain ini, aplikasi tidak perlu membuat koneksi database baru di setiap endpoint, sehingga kode menjadi lebih rapi dan lebih mudah dikembangkan.
